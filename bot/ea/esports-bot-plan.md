# План: Бот аналитики ставок CS2 / Dota2

---

## Фаза 1 — Фундамент (база проекта)

### Шаг 1. Структура проекта
- Создаём папку проекта, виртуальное окружение Python
- Устанавливаем зависимости: `aiogram`, `telethon`, `aiohttp`, `beautifulsoup4`, `playwright`, `sqlalchemy`, `apscheduler`, `redis`
- Создаём `.env` файл для токенов и ключей

### Шаг 2. База данных
- Выбираем PostgreSQL (или SQLite для старта)
- Создаём таблицы: `teams`, `players`, `matches`, `patches`, `telegram_messages`, `users`
- Настраиваем SQLAlchemy модели

---

## Фаза 2 — Сборщики данных (Collectors)

### Шаг 3. OpenDota API (Dota2) — начинаем с него, он бесплатный
- Подключаемся к `api.opendota.com`
- Собираем: профессиональные матчи, команды, игроков, статистику героев
- Сохраняем в БД

### Шаг 4. HLTV парсер (CS2)
- HLTV блокирует ботов — используем `playwright` (headless браузер) + ротацию User-Agent
- Собираем: рейтинг команд, предстоящие матчи, статистику игроков
- Добавляем задержки между запросами (3–5 сек)

### Шаг 5. Liquipedia парсер
- Используем Liquipedia API (частично открытый) + HTML парсинг
- Собираем: турниры, составы команд, расписание

### Шаг 6. Telegram-каналы (Telethon)
- Регистрируем Telegram App на `my.telegram.org` — получаем `api_id` и `api_hash`
- Подключаемся через Telethon как обычный пользователь (не бот)
- Читаем сообщения из списка каналов
- Парсим упоминания команд/игроков по словарю

### Шаг 7. Парсер патчей
- Мониторим страницы патч-ноутов CS2 (`store.steampowered.com`) и Dota2 (`dota2.com`)
- Сохраняем версию, дату, список изменений

---

## Фаза 3 — Планировщик (Scheduler)

### Шаг 8. APScheduler
- Каждые **2 часа** — обновление предстоящих матчей
- Каждые **6 часов** — обновление статистики команд и игроков
- Каждые **24 часа** — обновление рейтингов
- Каждые **60 сек** — проверка новых сообщений в Telegram-каналах
- **Ночью (02:00–06:00 UTC)** — тяжёлые задачи обновления

---

## Фаза 4 — Агрегатор и Анализатор

### Шаг 9. Aggregator
- Объединяем данные об одной команде из разных источников в один объект
- Нормализуем названия (например, "Natus Vincere", "NaVi", "Na\`Vi" → один ключ)
- Считаем производные метрики: форма команды (последние 5 матчей), head-to-head

### Шаг 10. Analyzer
- Принимает запрос (матч / команда / игрок)
- Собирает все данные из БД
- Формирует структурированный текстовый отчёт
- Помечает данные "до патча" / "после патча"
- **Никаких прогнозов — только факты и цифры**

---

## Фаза 5 — Telegram-бот (aiogram)

### Шаг 11. Команды бота
| Команда | Описание |
|---|---|
| `/start` | Регистрация, приветствие |
| `/upcoming cs2` | Список матчей CS2 на 48 часов |
| `/upcoming dota2` | Список матчей Dota2 на 48 часов |
| `/match NaVi vs Vitality` | Отчёт по матчу |
| `/team NaVi` | Отчёт по команде |
| `/player s1mple` | Отчёт по игроку |
| `/patch cs2` | Последний патч CS2 |
| `/patch dota2` | Последний патч Dota2 |
| `/help` | Список всех команд |

### Шаг 12. Форматирование отчётов
- Markdown-разметка Telegram (жирный, моноширинный шрифт)
- Если отчёт > 4096 символов — разбиваем на части
- Inline-кнопки для навигации между разделами

### Шаг 13. Кэш (Redis)
- Кэшируем готовые отчёты на 15–30 минут
- Не долбим БД и внешние сайты при повторных запросах

## Фаза 6 — Админка

### Шаг 14. Команды администратора
| Команда | Описание |
|---|---|
| `/admin add_channel @название` | Добавить Telegram-канал |
| `/admin remove_channel @название` | Убрать канал |
| `/admin list_channels` | Список всех каналов |
| `/admin status` | Состояние всех компонентов |

## Фаза 7 — Деплой

### Шаг 15. Запуск на сервере
- VPS минимум 2GB RAM (Hetzner, DigitalOcean, Timeweb)
- Docker + docker-compose для всех компонентов
- PostgreSQL + Redis в контейнерах
- Логи через модуль `logging` Python

│   ├── models.py        # SQLAlchemy модели

├── scheduler/
│   └── scheduler.py     # Планировщик задач
├── cache/

├── .env                 # Токены и ключи (не коммитить)
